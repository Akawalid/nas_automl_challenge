# Schedule Configuration (`schedule/`)

Defines the growth schedule: which layers grow, when, how many neurons, and how much training happens between growth steps.

The schedule is auto-generated by `tools/create_growth_schedule.py` when `general.generate_schedule=true`. It produces a sequence of steps, each being one of:
- **`SGD`**: Standard training epoch
- **`growth`**: Network growth step (add neurons to a specific layer)
- **`completion`**: Finalize all pending growth operations

## Parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `num_layers` | int \| null | `null` | Number of growable layers. `null` = auto-detected from the model. |
| `layer_order` | list[int] \| null | `null` | Order of growth steps. `null` = sequential indices `0 … num_layers-1`. The reserved value **`-1`** means one step that grows **all** layers at once (same as `layer_index=-1` in the CSV). Examples: `[-1]` only; or `[0, -1, 2]`.
| `epochs_between_growth` | int | `1` | Number of SGD training epochs between consecutive growth steps. `-1` = no growth (train-only mode). `0` = back-to-back growth steps with no training in between. |
| `growth_steps_per_layer` | int | `10` | Number of growth steps applied to each layer. `-1` = skip growth entirely. `0` = no growth steps. |
| `growth_size` | list[int] \| null | `null` | Maximum neurons to add per growth step. `null` = auto (determined by the growth algorithm, reported as `-1`). If a list, it may contain one value to broadcast to every layer, or one value per layer. |
| `training_steps_after_growth` | int | `100` | Number of full SGD training epochs after all growth steps are complete. |
| `output_file` | str \| null | `null` | Path to save the generated schedule as a CSV. `null` = don't save to a separate file (still logged as MLflow artifact). |
| `include_completion_step` | bool | `false` | Whether to add a final `completion` step that calls `model.complete_growth()`. |

## Grow all layers in one growth step

When a schedule step is (`growth`, `-1`, `max_neurons`, `batch_limit`), training runs **one** growth step that updates **every** growable layer (`perform_growth_step` in `aux_train_and_grow.py`). Per-layer metrics are logged as `layer_0_gamma`, `layer_0_added_neurons`, …; `added_neurons` is the **sum** over layers; the function returns `last_updated_layer == -1`.

## Schedule Generation Logic

The generated schedule follows this pattern:

```
For each layer in layer_order:
    Repeat growth_steps_per_layer times:
        1. [growth] Grow the current layer
        2. [SGD] × epochs_between_growth training epochs

[SGD] × training_steps_after_growth final training epochs
[completion] (if include_completion_step=true)
```

The total number of steps is:
```
len(layer_order) × growth_steps_per_layer × (1 + epochs_between_growth) + training_steps_after_growth + (1 if include_completion_step)
```

## Available Configs

| Config | Growth | Training After | Description |
|--------|--------|----------------|-------------|
| `default.yaml` | 10 steps/layer, 1 SGD between | 100 | Standard schedule |
| `classic.yaml` | 0 (no growth) | 250 | Pure training, no growth |
| `minimal.yaml` | 1 step/layer, 1 SGD between, 3 neurons | 3 | Minimal for testing |
| `debug_no_growth.yaml` | 0 (no growth) | 40 | Short training for debugging |
| `debug_no_train.yaml` | 4 steps/layer, 0 SGD between, 5 neurons | 0 | Growth only, no training |
| `end_to_front_layer_order.yaml` | (inherits default) | (inherits) | Grows layers from end to front: [7,3,6,2,5,1,4,0] |
| `front_to_end_layer_order.yaml` | (inherits default) | (inherits) | Alternating front/back: [0,4,1,5,2,6,3,7] |
| `first_block_first_front_to_end_layer_order.yaml` | (inherits default) | (inherits) | Sequential: [0,1,2,3,4,5,6,7] |

## Batch Limit in Schedule

Each schedule step includes a `batch_limit` field that controls how many batches are used:
- For **growth steps**: limits batches for computing statistics
- For **SGD steps**: limits batches for training
- Values: integer (exact count), float in (0,1] (fraction), `"hyper-parameter"` (defer to `growing.batch_limit` config), or `-1` (use all batches)
